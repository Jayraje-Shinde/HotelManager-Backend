Restaurant + Bar POS System - PostgreSQL ERD Reference
==========================================================

1. AUTH & ACCESS CONTROL
------------------------
roles
-----
- id (PK)
- role_name (varchar, unique)
- description (text)

users
-----
- id (PK)
- name (varchar)
- role_id (FK → roles.id)
- email (varchar, unique)
- password_hash (varchar)
- is_active (boolean, default true)
- created_at (timestamp)

Relationships:
roles (1) → users (many)
users are referenced by bill, kot, purchase, and excise_transaction.

----------------------------------------------------------

2. INVENTORY MANAGEMENT
-----------------------
category
--------
- id (PK)
- name (varchar)
- is_liquor (boolean)

unit
----
- id (PK)
- name (varchar)
- description (varchar)
- conversion_to_base (numeric)
- base_unit_id (optional self-reference)

item
----
- id (PK)
- name (varchar)
- category_id (FK → category.id)
- unit_id (FK → unit.id)
- tax_rate (numeric)
- selling_price (numeric)
- purchase_price (numeric)
- stock (numeric, default 0)
- duty_per_unit (numeric)
- is_available (boolean, default true)

stock_movement
--------------
- id (PK)
- item_id (FK → item.id)
- change_qty (numeric)
- reason (varchar)
- ref_type (varchar)
- ref_id (int)
- created_at (timestamp)

Relationships:
category (1) → item (many)
unit (1) → item (many)
item (1) → stock_movement (many)

----------------------------------------------------------

3. PURCHASES & SUPPLIERS
------------------------
vendor
------
- id (PK)
- name (varchar)
- contact (varchar)
- license_no (varchar)
- type (varchar)

purchase
--------
- id (PK)
- vendor_id (FK → vendor.id)
- total_amount (numeric)
- invoice_no (varchar, unique)
- purchase_date (date)
- created_by (FK → users.id)

purchase_item
-------------
- id (PK)
- purchase_id (FK → purchase.id)
- item_id (FK → item.id)
- quantity (numeric)
- price (numeric)

Relationships:
vendor (1) → purchase (many)
purchase (1) → purchase_item (many)
item (1) → purchase_item (many)

----------------------------------------------------------

4. SALES, BILLING & PAYMENTS
----------------------------
bill
----
- id (PK)
- table_no (int)
- user_id (FK → users.id)
- total_amount (numeric)
- discount (numeric)
- payment_mode (varchar)
- bill_date (timestamp)
- status (enum: active, cancelled, paid)

bill_item
---------
- id (PK)
- bill_id (FK → bill.id)
- item_id (FK → item.id)
- quantity (numeric)
- rate (numeric)
- subtotal (numeric)

payment
-------
- id (PK)
- bill_id (FK → bill.id)
- method (varchar)
- amount (numeric)
- reference_no (varchar)
- created_at (timestamp)

table_status
-------------
- id (PK)
- table_no (int, unique)
- status (enum: vacant, occupied, reserved)
- current_bill_id (FK → bill.id)

Relationships:
bill (1) → bill_item (many)
bill (1) → payment (many)
bill (1) → kot (many)
bill (1) → table_status (1)
item (1) → bill_item (many)

----------------------------------------------------------

5. KITCHEN ORDERS (KOT)
-----------------------
kot
---
- id (PK)
- table_no (int)
- waiter_id (FK → users.id)
- bill_id (FK → bill.id)
- status (enum: open, sent, served, cancelled)
- kot_no (varchar)
- created_at (timestamp)
- updated_at (timestamp)

kot_item
--------
- id (PK)
- kot_id (FK → kot.id)
- item_id (FK → item.id)
- quantity (numeric)
- note (text)

Relationships:
kot (1) → kot_item (many)
users (1) → kot (many)
bill (1) → kot (many)

----------------------------------------------------------

6. EXCISE (LIQUOR COMPLIANCE)
-----------------------------
excise_transaction
------------------
- id (PK)
- item_id (FK → item.id)
- excise_type (enum: opening, purchase, sale, breakage, closing)
- quantity (numeric)
- duty_value (numeric)
- ref_id (int)
- transaction_date (date)
- created_by (FK → users.id)

Relationships:
item (1) → excise_transaction (many)
users (1) → excise_transaction (many)

----------------------------------------------------------

7. RELATIONAL SUMMARY (Top-Down Layout)
---------------------------------------
ROLES → USERS
USERS → BILL
USERS → KOT
USERS → PURCHASE
USERS → EXCISE_TRANSACTION
CATEGORY → ITEM
UNIT → ITEM
ITEM → STOCK_MOVEMENT
ITEM → PURCHASE_ITEM
ITEM → BILL_ITEM
ITEM → KOT_ITEM
ITEM → EXCISE_TRANSACTION
VENDOR → PURCHASE → PURCHASE_ITEM
BILL → BILL_ITEM
BILL → PAYMENT
BILL → KOT
BILL → TABLE_STATUS (current_bill_id)
KOT → KOT_ITEM

----------------------------------------------------------
